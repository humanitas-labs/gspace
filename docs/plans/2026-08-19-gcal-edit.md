## Context

Implements humanitas-labs/gspace#1. Rescheduling an event today means `rm` + `add`,
which emails attendees a cancellation followed by a brand-new invite and mints
a fresh Meet link each time. `gcal edit <event-id>` patches the event in place
via `events.patch` with `sendUpdates=all`, so the event id and Meet link
survive and attendees get a single "updated event" notification.

Out of scope (per the issue): recurrence editing, per-instance edits. Also out
of scope: editing all-day events (rejected with a directed error) and clearing
the attendee list to empty.

## Changes

1. **`src/api/http.rs` — `JsonClient::patch_json`.** Mirror of `post_json`
   using `http.patch`; same error mapping.

2. **`src/api/calendar.rs` — get + patch.**
   - `EventPatch` — all-`Option` field set (summary, location, description,
     start, end, attendees); `None` fields are omitted from the body so the
     server leaves them untouched.
   - `get_event` — GET `/calendars/{id}/events/{eventId}` → `EventView`.
   - `patch_event` — PATCH the same path with `sendUpdates=all`, body built by
     `CalendarEventPatchRequest::from_patch` (every field
     `skip_serializing_if`).

3. **`src/gcal.rs` — `GcalEditArgs` + dispatch.** Positional `event_id`; flags
   mirror `add` but all optional: `--title`, `--start`, `--end` (conflicts
   with `--duration`), `--duration` (no default, unlike `add`'s 30),
   `--attendees` (comma-separated, replaces the list), `--location`,
   `--notes`, `--calendar` (default `primary`).

4. **`src/commands/calendar/edit.rs` — the handler.** Validates that at least
   one field flag was passed. Metadata-only edits patch directly. Any time
   flag triggers a `get_event` first so `resolve_times` can (a) preserve the
   duration when only `--start` moves, (b) validate end > start when only one
   side changes, and (c) reject all-day events (boundaries without a
   `dateTime`). Both start and end are always patched together when either
   changes. Output mirrors `add` (`event updated: …` block; `EventView` JSON
   with `--json`). Reuses `parse_datetime`, `format_when`, and
   `normalize_attendees` (promoted to `pub(crate)` in `add.rs`).

## Verification

1. `cargo test` — new clap, patch-body, and `resolve_times` tests plus no
   regressions.
2. Live round-trip:
   - `gcal add --title "edit test" --start "tomorrow 10:00" --meet --attendees <self>` — note id and Meet link.
   - `gcal edit <id> --start "tomorrow 11:00"` — same id, same Meet link,
     duration still 30m, one "updated" email (no cancellation).
   - `gcal edit <id> --title renamed --notes n --location l` — metadata-only
     patch, no GET.
   - Error paths: no flags → "nothing to update"; `--end` before start →
     rejected; `--end` + `--duration` → clap conflict.
   - `gcal edit <id> --json` returns the `EventView` JSON.
   - `gcal rm <id>` cleans up.
